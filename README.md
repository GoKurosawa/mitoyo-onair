## 何を探すか

- **月次**：Apple iTunes Search APIの`entity=podcast`による番組タイトル検索。対象は三豊・みとよ・仁尾・詫間・高瀬・山本・豊中・財田・観音寺・琴平・丸亀の11語です。タイトル検索が空のときだけ同じAPIで一般検索します。１検索20結果まで、各語最大２呼出です。網羅的なウェブ検索ではありません。
- 地名が番組名／公開著者表記に実際に現れる結果だけを候補化します。高瀬・山本・豊中は特に曖昧な一般名として記録します。地元番組と確認済みだとは扱いません。
- **週次**：既存の`rss: null`だけが対象です。登録済みRSSは上書きしません。公開Spotify HTML、運営者が確認済みの公式ホスティングページ、Appleの`feedUrl`から候補を探します。非公開API・埋込トークン解析・検索エンジンのスクレイピング・推測パス生成は行いません。
- Spotifyはログイン不要のHTMLだけを読みます。保護・取得失敗はスキップしてエラーを記録します。JavaScript内のトークンや非公開APIは利用しません。HTMLに公式外部リンクが出ないと進めないことがあります。
- 未発見は**番組停止・RSS無効を意味しません**。検出率より誤登録防止を優先します。

## 自動連携条件

次のどちらかに加え、番組名または運営者登録済み`aliases`との正規化完全一致が必要です。正規化はUnicode NFKC、小文字化、空白の統一だけで、句読点・絵文字を勝手に削除しません。

1. `official_urls`に運営者が登録した公式ホスティング番組ページに実在するRSSリンク。`link rel=alternate`のRSS/Atom MIME、または明示的な`a href`の末尾`/rss`・`/feed`・`.rss`・`.xml`だけを抽出します。今回のパーサーが取り込めるのはRSS 2.0のchannel形式だけです。
2. RSSのchannel直下の`link`が既存と同じSpotify番組ID、またはそのchannelからリンクされた許可済みホスティング**番組ページ**の実際の`a href`が同じSpotify番組IDです。エピソード本文・説明・SNS投稿・任意の第三者ページの言及は証拠にしません。

Appleのタイトルや著者一致だけでは自動登録しません。著者・画像・エピソード類似も根拠にしません。複数の同一性確認済みRSSは要確認に保留します。１番組の探索中に取得失敗があれば、その番組を自動登録しません。実行全体にエラーがあればその回は`programs.json`の探索による更新をすべて見送り、成功していた仮登録の週次マーカーも外して再試行します。

許可アダプターは`anchor.fm/<番組>`、`creators.spotify.com/pod/show/<番組>`、`podcasters.spotify.com/pod/show/<番組>`、`listen.style/p/<番組>`、`stand.fm/channels/<番組>`、`radiotalk.jp/program/<番組>`に限定しています。新しいホストやパス構造はコードとテストをレビューして追加します。許可ホストであることだけで運営者の公式URLリストに自動追加することはありません。

## 番組設定と手動レビュー

14件のSpotify URL／IDと出演者表記は、提供された最新サイトのカードから取得しました。外部調査で本人確認したという意味ではありません。カードには公式ホスティングページへのリンクがないため、`official_urls`は全件空です。`aliases`も勝手に表記違いを推測せず空にしています。Appleへの既存リンク３件はApple IDも保持しています。既存RSS３件は変更していません。

`discovery_candidates.json`は候補の累積履歴です。候補は公開タイトル・著者・Apple ID・検証可能なURL・検索語・日時・要確認理由・`status`を保持します。初期状態は`pending_review`です。運営者が`approved`／`rejected`等に変えても再探索で上書きしません。ただし`approved`にするだけでは自動掲載されません。Apple ID／フィードURLで重複を統合し、既存Apple ID／登録済みフィードは月次候補から除外します。Appleの検索結果にSpotify IDは通常ないため、Appleのみでは未登録候補のSpotify IDまで同定しません。

RSSを手動承認するときは実フィードを確認し、必要なら`aliases`を追加し、`rss`と実際のchannelタイトルの`rss_title`、根拠を登録してください。自動登録時も`rss_title`と`rss_provenance`を保存します。日次更新は`rss_title`があればその文字列との完全一致、なければ従来どおり`name`との完全一致を検証します。任意のタイトルへ合わせてチェックを解除することはありません。

## 時期・状態・障害

- 既存の毎日日本時間6:17ごろのActions内で、探索→日次RSS更新→従来どおり配備します。実行時刻はGitHub側の遅延を受けます。
- 月次は日本時間の暦月で判断。１日固定ではなく、その月の最初の成功実行で完了します。検索語ごとの成功マーカーを保存するため一部失敗は翌日の実行で未完了語だけ再試行します。
- 週次は番組ごとの最後の成功確認から経過７日。取得に失敗した番組の日時は進めず翌日に再試行します。成功して何も見つからなかった場合は７日後です。削除済み番組は探索対象にせず、古いマーカーと手動レビュー履歴は削除しません。
- 月次の累積記録は`discovery_state.json`の`monthly_reports[YYYY-MM]`に残します。`discovery_report.md`は最新実行の要約です。候補履歴と月別記録は自動削除しません。
- 通常初回で最大11番組＋11語を確認します。限定実行で残った対象は次の実行で追いつきます。`--force`は確認間隔を無視しますが、既にRSS登録済みの番組は対象外です。
- 探索失敗はActionsの`continue-on-error`で日次更新から分離します。日次RSS自体の全件失敗時の停止動作は維持しています。
- Actionsが保存対象に追加するのは既存`index.html`・`rss_cache.json`と、存在する`programs.json`・`discovery_state.json`・`discovery_candidates.json`・`discovery_report.md`だけです。無差別な`git add .`は使いません。Issue権限は不要で、既存の`contents: write`だけです。
- GitHub側に別のビルド自動起動があればCloudflareへの二重配備が残る可能性があります。今回は関係ない配備設定を変更していません。

## 安全性と上限

標準ライブラリのみ。HTTP(S)の公開ホストだけを許可し、ユーザー情報・クエリ・フラグメントつきURLは安全側に除外します（Apple APIの固定エンドポイントのみ検索クエリ例外）。このためクエリ必須の正規公開RSSでも見つからない場合があります。DNSで返った全IPを検査し、私設・ループバック・リンクローカル・IPv6ローカル等を拒否します。接続直前にも再検査し、検査済みの数値IPへ接続し、TLSのホスト名検証を維持します。全リダイレクトでもURL検査を行い、システムのプロキシ環境変数は使いません。ネットワーク境界の完全な防御を保証するものではありません。

HTMLは2MiB、探索用RSSは8MiB、日次RSSは12MiBまで。１リクエスト15秒、探索全体のネットワーク受付は480秒・80要求までです（読み込み中の低速送信に対する厳密な全体タイムアウトではありません。Actions全体15分が最終上限です）。Appleは実API呼出間隔3.2秒以上・実行内キャッシュあり。テストは時計と待機をモックします。XMLのDOCTYPE／ENTITY／NULを拒否し、UTF-16を含む危険なXMLも取り込みません。

メールアドレス・生XML・説明本文・認証情報は保存しません。エラーは固定コードにし、外部例外メッセージや秘密つきURLをログに出しません。要約MarkdownはHTML・記号をエスケープし、外部URLをリンクとして展開しません。JSON URLを開く前も運営者が確認してください。ファイルは１ファイルごとに一時ファイルから置換しますが、複数ファイルを一括更新するデータベーストランザクションではありません。

## 手動実行・検証

```
python -m unittest discover -v
python discovery.py --dry-run --max-programs 1 --max-monthly-queries 1
python discovery.py --force
```

`--dry-run`は標準出力だけで、設定・状態・候補・レポートへ書き込みません。`--max-programs 0`や`--max-monthly-queries 0`で片側を止められます。終了コードは成功0、個別エラーあり1、入力等で中断2です。

最終版は33テスト（既存５＋探索・安全性28）が成功しました。限定実通信は既存１番組＋月次１語で実施し、Apple呼出２件、候補０件、エラー０、終了0でした。初回の試作ドライランでは10候補でしたが、一般名の過剰候補化を防ぐため地名が公開タイトル・著者に出現する条件を追加し、最終実行で０件となりました。これは既存番組１件の公開HTML読取とAppleの疎通の確認であり、全11語・全番組の探索やRSSの自動登録成功を証明するものではありません。スナップショット比較で入力ファイルの変更がないことを確認しました。検証結果の詳細は納品時の実行記録を参照してください。
